# TCP/IP

Использовать этот раздел, когда нужно объяснить, как Интернет работает на практике, без избыточной абстракции OSI.

## Простое объяснение

TCP/IP - это семейство протоколов, на котором реально работает Интернет. IP отвечает за адресацию и доставку пакетов между сетями, а TCP и UDP - за передачу данных приложениям.

## Техническое объяснение

Стек TCP/IP обычно рассматривают как 4-уровневую модель: Link, Internet, Transport, Application. В ней инкапсуляция идет сверху вниз, а маршрутизаторы в основном принимают решения на Internet layer, не разбирая прикладную полезную нагрузку.

## История

- Истоки - ARPANET и ранние интернет-эксперименты.
- MDN отмечает, что история Интернета начинается в 1960-х и переходит к публичной инфраструктуре в 1980-х.
- Современная спецификация TCP собрана в RFC 9293, IPv6 - в RFC 8200.

## Компоненты

- Link: Ethernet, Wi-Fi
- Internet: IPv4, IPv6, ICMP
- Transport: TCP, UDP
- Application: DNS, HTTP, SMTP, SSH

## Схема инкапсуляции

```text
HTTP request
  -> TCP segment
    -> IP packet
      -> Ethernet frame
```

## Типичные ошибки

- Путать TCP/IP только с TCP. IP и TCP - не одно и то же.
- Считать, что IP гарантирует доставку и порядок. Это делает не IP.
- Игнорировать транспортный и прикладной слой при рабочем маршруте.

## Диагностика

- Проверить IP-адрес и маршрут
- Проверить reachability до удаленного IP
- Проверить нужный transport protocol и порт
- Проверить прикладной протокол

## Лучшие практики

- Объяснять любую проблему цепочкой `application -> transport -> IP -> link`.
- Различать адресацию, маршрутизацию и надежность доставки.
- Для любого сервиса фиксировать: какой IP, какой transport, какой port, какой путь возврата.
