# TCP vs UDP

Использовать этот раздел, когда нужно выбрать транспортный протокол, объяснить поведение сервиса или понять, почему один поток чувствителен к потерям, а другой - к задержкам.

## Простое объяснение

TCP делает доставку надежной и упорядоченной. UDP делает доставку быстрой и простой, но без гарантий.

## Техническое объяснение

TCP - connection-oriented transport с handshake, sequence numbers, acknowledgements, retransmission и flow/congestion control. UDP - connectionless datagram protocol с минимальным заголовком и без встроенных гарантий доставки или порядка.

## История

- UDP стандартизован в RFC 768.
- TCP исторически был RFC 793, а актуальная консолидированная спецификация - RFC 9293.
- Рост real-time трафика сделал компромисс TCP/UDP особенно заметным в VoIP, видеостриминге и DNS.

## Сравнение

| Свойство | TCP | UDP |
| --- | --- | --- |
| Соединение | Есть | Нет |
| Порядок доставки | Гарантируется | Не гарантируется |
| Повтор потерянных данных | Есть | Нет |
| Контроль перегрузки | Есть | Нет на уровне протокола |
| Задержка старта | Выше | Ниже |
| Типичные сценарии | HTTPS, SSH, SMTP | DNS, VoIP, gaming, telemetry |

## Типичные заблуждения

- "UDP лучше TCP, потому что быстрее" - не всегда; для критичных данных потери могут сделать приложение хуже.
- "UDP не имеет портов" - имеет, RFC 768 определяет source и destination port.
- "TCP всегда медленнее" - при нормальной сети TCP может быть оптимальным за счет надежности и управления потоком.

## Диагностика

- TCP: смотреть handshake, retransmissions, window, resets.
- UDP: смотреть факт отправки/приема, потерю, jitter, application-level retry.
