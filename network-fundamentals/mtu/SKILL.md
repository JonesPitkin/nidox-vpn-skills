# MTU

Использовать этот раздел, когда есть симптомы вида "часть сайтов открывается, часть зависает", "через VPN медленно", "QUIC работает, а TCP ломается" или "большие пакеты пропадают".

## Простое объяснение

MTU - максимальный размер IP-пакета, который можно передать по конкретному каналу без фрагментации. MSS - максимальный размер полезных TCP-данных внутри сегмента.

## Техническое объяснение

MTU привязан к каналу или логическому интерфейсу. Для IPv4 возможна фрагментация маршрутизаторами, хотя практически это нежелательно. Для IPv6 маршрутизаторы не фрагментируют транзитные пакеты; критична корректная работа PMTUD по RFC 8201 и ICMPv6.

## История

- Классическая PMTUD для IPv4 описана в RFC 1191.
- IPv6 PMTUD описана в RFC 8201.
- MSS исторически связан с RFC 879 и развитием TCP.

## Компоненты

- MTU интерфейса
- IP fragmentation
- DF bit в IPv4
- ICMP Fragmentation Needed / Packet Too Big
- PMTUD
- TCP MSS

## Типичные заблуждения

- "Если уменьшить MTU, всегда станет лучше" - не всегда; можно потерять throughput.
- "MSS и MTU одно и то же" - нет, MSS меньше MTU, так как TCP/IP заголовки занимают место.
- "ICMP можно смело полностью блокировать" - это часто ломает PMTUD, особенно в IPv6.
