# OSI Model

Использовать этот раздел, когда нужно разложить сетевую проблему по уровням и не смешивать физическую неисправность, IP-маршрутизацию, DNS и прикладной протокол в одну причину.

## Простое объяснение

OSI - это учебная модель, которая делит сетевое взаимодействие на 7 уровней, чтобы было проще понять, где именно ломается связь.

## Техническое объяснение

OSI не описывает Интернет "как он реализован байт в байт". Это абстракция ISO, которая помогает отделить физическую передачу сигнала, канальную доставку кадров, межсетевую доставку пакетов, транспорт, сеансы, представление данных и приложения. В реальной эксплуатации стек TCP/IP проще, но диагностическая ценность OSI остается высокой.

## История

- Разработана ISO как эталонная модель межсистемного взаимодействия.
- Исторически стала общим языком для инженеров и преподавания сетей.
- Современный Интернет строится не строго по OSI, а ближе к TCP/IP, но термины L2, L3, L4 и L7 используются повсеместно.

## Уровни и типовые примеры

| Уровень | Что делает | Примеры |
| --- | --- | --- |
| L1 Physical | Передает биты | кабель, оптика, радиоканал |
| L2 Data Link | Передает кадры в пределах сегмента | Ethernet, Wi-Fi, MAC |
| L3 Network | Доставляет пакеты между сетями | IPv4, IPv6, ICMP |
| L4 Transport | Доставляет данные процессам | TCP, UDP |
| L5 Session | Управляет логикой сеанса | части SMB, RPC, TLS-сеанс в прикладном контексте |
| L6 Presentation | Представление и кодирование данных | TLS, ASN.1, JSON encoding в практическом смысле |
| L7 Application | Логика приложения | HTTP, DNS, SMTP |

## Принцип работы

```text
приложение
  -> формирует полезные данные
  -> передает их вниз по стеку
  -> каждый уровень добавляет свой заголовок
  -> на приемнике заголовки снимаются в обратном порядке
```

## Основные компоненты и инструменты

- L1: `ethtool`, индикация линка, SFP/кабельные тесты
- L2: `ip link`, `bridge`, `arp`, `tcpdump -e`
- L3: `ip addr`, `ip route`, `ping`, `traceroute`
- L4: `ss -lntup`, `nc`, `tcpdump 'tcp or udp'`
- L7: `curl`, `dig`, `openssl s_client`

## Типичные ошибки и заблуждения

- "Ping работает, значит сеть исправна" - нет, может быть сломан DNS, TCP/443 или MTU.
- "OSI точно соответствует Интернету" - нет, это модель, а не буквальная реализация.
- "DNS - это всегда отдельный слой" - практически DNS относят к приложению, хотя он зависит от L3/L4.

## Лучшие практики

- Диагностировать снизу вверх: link -> L2 -> IP -> маршрут -> transport -> application.
- Формулировать проблему по слоям: "нет carrier", "нет ARP", "нет default route", "TCP SYN уходит без SYN-ACK", "DNS отвечает NXDOMAIN".
- Использовать OSI как язык общения, а не как догму.
