# Примеры OSI

## Сценарий 1. "Wi-Fi есть, Интернет не работает"

Разбор по слоям:

1. L1/L2: клиент ассоциирован с Wi-Fi, link есть.
2. L3: клиент получил адрес `192.168.1.20/24`, но gateway неверный.
3. L4/L7: не проверяем до исправления L3.

Вывод: симптом выглядел как "Интернет умер", но первопричина - ошибка адресации.

## Сценарий 2. "Пингуется IP, но сайт не открывается"

```text
ping 1.1.1.1            -> работает
dig example.com         -> timeout
curl https://1.1.1.1    -> TCP есть, но это не равно доступности нужного сайта
```

Вывод: вероятнее всего проблема в L7/L4 для DNS, а не в базовой IP-связности.

## Сценарий 3. "Сервис слушает, но извне недоступен"

- L4 локально: `ss -lntp` показывает `0.0.0.0:443`
- L3: маршрут наружу есть
- L4/L3 на границе: firewall или NAT не пропускает входящий SYN

## Частые вопросы

### С чего начинать диагностику?

С самого нижнего подтверждаемого уровня. Если нет линка, DNS бессмысленно разбирать.

### Когда модель OSI вредна?

Когда ее используют как догму и игнорируют реальные стековые особенности TCP/IP, QUIC, NAT и firewall state.
