## Проверка команд Linux и OpenWrt

### Linux

- Статус: `PASS WITH NOTES`
- Командный набор в целом актуален и технически корректен.
- Желательно модернизировать часть примеров:
  - вместо `arp -an` предпочесть `ip neigh`;

- Некоторые команды зависят от установленных пакетов:
  - `tracepath`, `conntrack`, `ethtool`, `nft`, `resolvectl` могут отсутствовать в минимальной системе.

### OpenWrt

- Статус: `PASS WITH NOTES`
- Набор выглядит актуальным для современного OpenWrt c `fw4`/`nftables`.
- Команды `ubus`, `ifstatus`, `uci`, `fw4`, `logread`, `tcpdump`, `nslookup` уместны.
- Важная оговорка:
  - `fw4` относится к современным OpenWrt-веткам; для legacy-систем на `fw3` команда будет иной.
  - `/etc/init.d/dnsmasq status` зависит от конкретной service-wrapper реализации и не так универсальна, как `logread` или проверка процесса.

## Улучшения для разделов с оценкой ниже 9

### `tcp-ip` — 8/10

Рекомендуемые улучшения:

- добавить отдельный краткий блок про различие host behavior и router behavior;
- добавить один практический end-to-end кейс "пакет проходит стек от клиента до сервера и обратно";
- в Linux-примерах добавить связку `ip route get` + `tcpdump` + `ss` как единый triage workflow.

### `routing` — 8/10

Рекомендуемые улучшения:

- расширить динамическую маршрутизацию хотя бы на уровне "что решают OSPF и BGP и чем отличаются";
- добавить пример route metric / preference / policy-based routing;
- добавить отдельный кейс по asymmetric routing и stateful firewall.

### `dns` — 8/10

Рекомендуемые улучшения:

- усилить пояснение по `TTL`, negative caching и stale cache behavior;
- добавить больше operational-примеров split DNS и split-horizon;
- при желании расширить список RFC по DNSSEC, если раздел будет расти.

### `ipv4` — 8/10

Рекомендуемые улучшения:

- добавить special-purpose blocks: `127.0.0.0/8`, `169.254.0.0/16`, `100.64.0.0/10`, `224.0.0.0/4`;
- добавить блок "почему overlap RFC1918-сетей ломает VPN";
- усилить примеры маршрутизации по более узкому/широкому префиксу.

### `ipv6` — 8/10

Рекомендуемые улучшения:

- добавить различие SLAAC, DHCPv6 и RA flags;
- добавить operational-блок по `ULA`, `GUA` и делегированию префиксов;
- усилить диагностику broken IPv6 preference в dual-stack.

### `ports` — 8/10

Рекомендуемые улучшения:

- добавить нюансы reuse/listen semantics и разницу между `0.0.0.0`, `127.0.0.1`, `::`;
- добавить пример QUIC/UDP на `443/udp` рядом с HTTPS на `443/tcp`;
- добавить заметку про ephemeral port exhaustion и влияние на NAT/CGNAT.
