# Аудит Skill `openwrt-cudy-wr3000s`

Дата аудита: 7 июня 2026 года.

## Результат

Skill проверен по актуальной странице Cudy WR3000S v1, OpenWrt Techdata, официальным release notes, `profiles.json`, исходникам DTS, коммитам OpenWrt и инструкции Cudy по TFTP recovery.

Обнаруженные фактические и временные неточности исправлены. Критических ошибок, которые после исправления делают установку или восстановление небезопасными, не осталось.

## Основные исправления

1. Обновлены версии OpenWrt:
   - current stable: 25.12.4;
   - current old-stable 24.10: 24.10.7;
   - 24.10.5 оставлена только как исторический минимум поддержки ESMT F50L1G41LC.
2. Исправлен статус `ubootmod`:
   - профиль `cudy_wr3000s-v1-ubootmod` реально выпущен в 25.12.4;
   - в 24.10.7 этого профиля нет;
   - обычная двухэтапная установка не подходит для миграции на OpenWrt U-Boot layout.
3. Уточнены известные NAND:
   - XMC XM25QH128C;
   - GigaDevice F50L1G41LB;
   - поздний ESMT F50L1G41LC.
4. Исправлена формулировка о производственном коде `2543`: это начало серийного номера/код партии, а не обычное числовое сравнение полного серийного номера.
5. OEM TFTP recovery дополнен официальными параметрами Cudy:
   - компьютер подключается к LAN;
   - адрес компьютера/TFTP-сервера `192.168.1.88`;
   - OEM firmware переименовывается в `recovery.bin`;
   - Reset удерживается до начала передачи или быстрого мигания LED.
6. Для Failsafe OpenWrt 24.10/25.12 указан SSH, удалена вводящая в заблуждение ссылка на telnet как обычный вариант.
7. Удалён лишний `umount /overlay` перед `jffs2reset`.
8. Уточнено, что `ethtool` может отсутствовать в базовом образе.
9. Уточнено назначение WAN LED: DTS задаёт функцию `WAN_ONLINE`, но фактический trigger нужно проверять в sysfs.
10. Добавлены прямые источники на release profiles и репозиторий Podkop.

## Дублирование

Повторяются только критичные факты:

- запрет образов других моделей;
- минимум 24.10.5 для ESMT NAND;
- предупреждение о `ubootmod`;
